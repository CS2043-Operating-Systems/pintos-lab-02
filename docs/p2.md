## Argument Passing

#### DATA STRUCTURES

**A1.** The launch data added in process.c is:

    struct start_info {
      char *command;
      struct child_record *child;
    };

- command: owns a page-sized command-line copy until the child parses it.
- child: points to load and exit state shared with the parent.
- program_name: keeps the executable name for the exit message after tokenization changes the command copy.

The child also temporarily allocates one page for argument pointers and another for their final stack addresses. Neither is retained after startup.

#### ALGORITHMS

**A2.** process_execute() copies the command line before creating a thread because the caller's original string may change or disappear. The child uses strtok_r() to split that copy on spaces and tabs. It loads argv[0] as the executable. push_arguments() copies the strings onto the user stack from last to first and records each string's final address. It aligns the stack to four bytes, pushes a null pointer, pushes the addresses in reverse order, then pushes argv, argc, and a fake return address. argv[0] through argv[argc - 1] therefore retain command order.

Before each string copy, the code checks the space left in the single stack page. It also checks the space needed for pointers and metadata after alignment. If the command does not fit, loading fails.

#### RATIONALE

**A3.** strtok() keeps parsing state in shared static storage. Two threads parsing command lines could overwrite each other's state. strtok_r() instead uses a save pointer owned by each caller.

**A4.** A shell can support quoting, escapes, variable expansion, and redirection before launching a program without placing those rules in the kernel. Different shells can also provide different command languages while the kernel keeps a simple execution interface.

## System Calls

#### DATA STRUCTURES

**B1.** The new per-thread fields under USERPROG are:

    struct list children;
    struct child_record *child_record;
    struct file *executable;
    char *program_name;
    int exit_status;
    bool user_process;
    struct list open_files;
    int next_fd;

- children: holds the process's direct children.
- child_record: links a child to its parent.
- executable: stays open to deny writes while the program runs.
- program_name: supplies the exit line.
- exit_status: is reported to the parent.
- user_process: prevents kernel threads from printing user exit lines.
- open_files: holds the process's file handles.
- next_fd: supplies the next local descriptor number.

The new shared state and file handle are:

    struct child_record {
      tid_t tid;
      int status;
      bool loaded;
      bool waited;
      int references;
      struct semaphore load_done;
      struct semaphore exit_done;
      struct lock lock;
      struct list_elem elem;
    };

    struct file_handle {
      int fd;
      struct file *file;
      struct list_elem elem;
    };

    struct lock filesys_lock;

- tid: identifies a direct child.
- status: stores its exit result.
- loaded: reports whether exec loading succeeded.
- waited: prevents a second wait.
- references and lock: protect the shared record's lifetime.
- load_done and exit_done: signal loading and termination.
- child_record.elem: links into the parent's children list.
- file_handle.fd and file: bind one local descriptor to an open file.
- file_handle.elem: links into open_files.
- filesys_lock: serializes access to the starter file system.

**B2.** open() allocates a file_handle, stores the result of filesys_open(), assigns the current process's next_fd, and adds the handle to that process's list. Lookup searches only that list. Numbers are unique within one process while allocated, not across the OS. Descriptors 0 and 1 are reserved for standard input and output. close() removes and frees one handle; exit closes the rest.

#### ALGORITHMS

**B3.** The handler reads the syscall number and required stack arguments through user_word(). Before a raw buffer is accessed, require_user_range() checks every page that it covers. A read() destination must also be writable. For a string argument, user_string() copies one byte at a time into a kernel page, checking the mapping before each byte and stopping at the null terminator. Invalid mappings terminate only the calling process with status -1. The file-system lock surrounds file operations after pointer checks.

**B4.** Counting only validation of a raw data buffer, a 4,096-byte transfer calls pagedir_get_page() once if page aligned and twice if it crosses a boundary. A two-byte transfer likewise needs one or two calls. read() also checks the writable bit once per covered page. The string path is less efficient: it calls pagedir_get_page() for every byte, so a 4,096-byte string ending in a null byte can cause 4,096 calls, and a two-byte string causes two. Caching the current page would cut the string cost to one or two checks. Stack argument checks add separate calls.

**B5.** wait() searches the caller's direct-child list and rejects unknown children and repeated waits. It blocks on that child's exit_done semaphore. On termination the child releases its resources and page directory, saves its status, and signals the semaphore. The parent reads the status, removes the record, and releases its reference. If the child exited earlier, the semaphore retains the signal and wait() returns immediately.

**B6.** Pointer checks live in user_word(), require_user_range(), and user_string() instead of being repeated in each file operation. The handler copies names and validates buffers before acquiring filesys_lock. For example, write() checks the source pages before file_write() takes that lock. create() reads the size argument before allocating its filename copy, so an invalid size argument cannot leave that copy behind. A bad pointer ends the process while no file-system lock is held. If copying a name fails through allocation pressure, the call returns failure; successful copies are freed by their syscall path. process_exit() closes any remaining descriptors and the executable, including after an exception.

#### SYNCHRONIZATION

**B7.** process_execute() creates a child_record before starting the child and waits on load_done. The child sets loaded after load() and stack construction, then signals load_done. The parent returns the child TID only on success; on failure it returns TID_ERROR. Parent and child each hold a record reference, so early child exit cannot free the result before the parent reads it.

**B8.** If wait() starts first, the parent blocks on exit_done. If the child exits first, the signal remains available with the saved status. After a successful wait, the parent removes the record and drops its reference. If the parent exits without waiting, it releases records in its children list; the child later releases its own reference. If the child exits first, it drops its reference and the parent later waits or discards the record. A lock guards the reference count. Invalid TIDs, nonchildren, and repeated waits return -1. For a failed exec, the parent waits for the child to finish releasing its process resources before removing the record and returning an error.

#### RATIONALE

**B9.** Page-by-page prevalidation keeps normal syscall paths readable and rejects invalid ranges before taking the file-system lock. Checking write permission for read() destinations avoids treating a read-only mapping as an output buffer. This is straightforward in the current non-VM project, though it makes a separate page-table pass and would need review for demand-paged memory.

**B10.** Keeping a list in each process makes descriptor ownership and exit cleanup simple. Different processes can safely use the same numbers. Finding a descriptor takes longer as the list grows, so a table would be faster with many open files. The numbers keep increasing and are not reused during one process lifetime.

**B11.** The Pintos thread ID is still the process ID. Each process has one thread in this project, so a separate set of process IDs is not needed.
